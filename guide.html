This guide covers two things: how to use the UAD Plugin Library database, and how UAD's own licensing system works — including the workaround for moving hardware between systems.

Part 1 — Using the UAD Plugin Library Database

The database has two views, switched via the tabs at the top: UAD Plugins and UAD Hardware.

Searching plugins

  • Type a plugin name into the search box. It searches across every system at once and shows which system(s) already have it.
  • No search term = shows the full list for whichever system tab is currently selected.
  • The system tabs (System 1–6) show a live count of how many plugins are in each.

Searching hardware

  • Switch to the UAD Hardware tab.
  • Search by asset ID, serial number, description, or PID.
  • The capacity bar at the top shows every system's hardware count as System X: n/6, turning red when a system is full. Six units is UAD's own hard limit per system — see Part 2.

Adding, removing, and moving — now password protected

Adding or removing a plugin, adding hardware, and moving hardware between systems all now require a password, to stop accidental edits or mistakes going straight in unchallenged.

  • Plugin edits (add / bulk-add / remove) are gated by one password, set or changed via the 🔒 link on the Plugins tab.
  • Hardware moves are gated by a separate password, set or changed via the 🔒 link on the Hardware tab.
  • Changing either password now requires entering the current password first — it can't just be overwritten by anyone who clicks the link.
Don't know the current password? Ask whoever administers the tool for the team (Phil). It isn't published here on purpose — this guide is hosted on the same public GitHub Pages site as the tool, and printing the password in a public document would defeat the point of having one.

Move hardware — an important distinction

The "Move" button on a hardware row only updates this database's own record — it does not touch the real UAD account, plugin authorization, or physical device registration in any way. If you use it, you still need to do the real-world UAD transfer described in Part 3, and vice versa: if you do a real UAD transfer, remember to update the record here to match.

Export / Import

The Export button downloads a full backup (plugins, hardware, and system assignments) as a JSON file. Import loads one back in. Since each person's additions save only to their own browser, this is the way to move your data to someone else or to a different machine — see the hosting guide for more on why.

Using the database to check a client spec

This is the main reason the tool exists — figuring out fast whether we can cover a client's plugin rider, and if not, what it'd take to get there.

  1. Get the client's plugin list. Riders typically name specific UAD plugins the engineer wants available.
  2. Search each plugin name in the UAD Plugins tab. For each one, note which system(s) currently have it.
  3. Look for a single system that covers the whole list. A piece of hardware only unlocks the plugins registered to its own system (Part 2 explains why). If the client's plugins are spread across two or three of our systems, no single rig we own can run all of them at once as things stand.
  4. For anything missing, work out which of these applies:
    • We own it, just on a different system → would need a hardware move (Part 3) to consolidate it onto the system going out to that job. Slow and has real trade-offs — read Part 3 before promising it.
    • We don't own it at all → straightforward purchase, then register it into the right system.
  5. Check hardware capacity too. Even where we hold the right plugins, adding a device to that system needs a free slot (see the capacity bar) — a system already at 6/6 can't take on more hardware, full stop.
  6. Adding anything missing now needs the edit password (see above) — if you're checking a spec but can't make the fix yourself, flag it to whoever holds the password rather than leaving the database out of date.
  7. Keep the answer simple for whoever's quoting the job: "covered as-is", "needs a plugin purchase", or "needs a hardware/system reshuffle" — and update the database once any of that actually happens, so it stays trustworthy for the next spec check.

Part 2 — How UAD Licensing Actually Works

The account → system → device → license hierarchy

  • Everything sits under one UA account (my.uaudio.com / uaudio.com account).
  • Within that account, hardware is grouped into Systems. A system is just a named bucket of UAD-2/Apollo/Satellite devices that all share one pool of plugin licenses.
  • UAD DSP plugin licenses are authorized to a System, not to an individual device. Any device sitting in that system can run any plugin licensed to that system — but only within that system.
  • A device in System 1 has zero access to plugins licensed under System 2 in the same account, even though it's the same account. This is exactly why our database is organized by system — it mirrors UAD's own structure, not something we invented.

The limits that actually bite

  • Six UAD-2/Apollo devices per system, hard cap, no exceptions. This is UAD's own limit — it's why our database enforces the same 6-unit cap on the hardware tab.
  • Licenses can't be split or cherry-picked in a transfer. Any transfer of hardware out of a system takes either zero plugins or every UAD DSP + perpetual UADx license in that entire system with it. There's no way to say "take these three plugins but not those two."
  • Once plugins are merged into a combined account, they can't be un-merged. If you ever transfer plugins into an account alongside hardware, that's permanent — UA will not split them back out later.
  • Registering a 7th device auto-creates a brand-new, empty system. It won't have access to any existing plugin licenses — you'd need to buy fresh licenses for it or physically move a device out of an existing (full) system to make room.
  • There's no self-service "move device between my own systems" button. UAD Customer Care will do this once, per account, as a manual courtesy — after that, or if you need it more than once, the only route left is the transfer-as-if-selling workaround in Part 3.
  • Warranty note: any hardware re-registered as "used" (which is exactly what the workaround in Part 3 involves) loses the original-owner warranty. Worth knowing before doing this on brand-new kit.

Source: Universal Audio's own support documentation (help.uaudio.com), current as of research date September 2026.

Part 3 — Moving Hardware Between Systems (the workaround)

Because there's no repeatable self-service way to move a device between our own systems, and because a straight transfer always drags every plugin license in that system along with it, the practical workaround is to route the device through a second, "dummy" UA account that holds no plugins of its own — using it purely as a relay so the hardware arrives at its destination system with nothing attached.

Before you start: this only works cleanly if you choose "No" to transferring plugins at every step below. If you accidentally say "Yes," the entire system's plugin library goes with the hardware, and — per Part 2 — that cannot be undone.

Step-by-step

  1. Set up (once) a dummy UA account. A separate email address registered at uaudio.com, used only as a relay — it should never hold any purchased plugins of its own.
  2. From the Solotech account, go to the Hardware page (uaudio.com account → Hardware) and find the device you want to move.
  3. Click Transfer a Device on that unit.
  4. When asked "Transfer Plug-ins?", select No. This is the critical step — it keeps every plugin license in its current system, and only the physical device leaves.
  5. Submit. The device now shows as pending transfer in the Solotech account and is no longer usable there.
  6. Log into the dummy account. Go to the Hardware Registration page (uaudio.com/pages/register), select the device type, choose Used, and enter the serial number.
  7. Install/open UA Connect and the UAD software if not already present, connect only that device, open UAD Meter & Control Panel, and click Authorize Plug-Ins. This completes registration into the dummy account — the device will pick up only the free Analog Classics bundle that comes with any used unit, nothing more, since no licenses were transferred.
  8. From the dummy account, immediately start a second transfer on the same device: Hardware page → Transfer a Device → again select No for plugins.
  9. Log back into the Solotech account and register the device again as Used hardware (same registration flow as steps 6–7, serial number → Authorize Plug-Ins). This time, when the system prompts you to choose which system to register it into, select the destination system — this is the point where the device actually lands where you want it.
  10. Click Authorize Plug-Ins in UAD Meter & Control Panel to finish. The device now has access to whatever plugins are already licensed to that destination system — which is the point of the whole exercise.
  11. Update our database: use the "Move" button on the hardware entry to relabel it to the new system (with the move password), so our records match what's actually registered with UAD.

A cheaper first option

Before doing any of the above, it's worth remembering UAD Customer Care will do one system-to-system move per account for free, no dummy-account dance required. If this hasn't been used yet on the Solotech account, that's the move to spend it on — save the workaround above for anything after that.

Practical caveats

  • UAD's own transfer step typically takes a couple of business days to process on their end — this isn't instant, so it needs to be planned ahead of a job, not done the morning of.
  • Registering hardware as "used" at any point in this process forfeits the manufacturer warranty for that unit going forward.
  • If a transfer is started by mistake, it can be cancelled while still pending — but only before the receiving account completes registration. Once registered on the other end, it's done.
